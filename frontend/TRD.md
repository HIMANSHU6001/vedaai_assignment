## **1. Overview**

### **1.1 Purpose**

This document specifies the frontend architecture for the VedaAI Assessment Creator. It defines the routing, state management, component hierarchy, real-time WebSocket integration, and data fetching strategies required to implement the provided Figma designs.

### **1.2 System Summary**

The frontend provides a dual-view interface (Inbox/Library tabs). Users can submit a complex multipart form (including PDF uploads) to create an assignment. Upon submission, the UI transitions to a real-time loading state driven by WebSockets, culminating in the rendering of a strictly formatted, academic-style Question Paper generated by the backend LLM.

### **1.3 Technology Stack**

| Field | Technology | Description |
| --- | --- | --- |
| **Framework** | Next.js 14+ (App Router) | React framework for routing and layout |

## **3. State Management (Zustand)**

A centralized store manages the asynchronous generation lifecycle, preventing prop-drilling between the form submission, the WebSocket listener, and the final rendering components.

```typescript
// src/store/useAssessmentStore.ts
import { create } from 'zustand';
import { QuestionPaperOutput } from '@/types';

type Status = 'idle' | 'submitting' | 'processing' | 'done' | 'failed';

interface AssessmentState {
  status: Status;
  jobId: string | null;
  assignmentId: string | null;
  paperData: QuestionPaperOutput | null;
  error: string | null;
  
  // Actions
  setStatus: (status: Status) => void;
  setIdentifiers: (jobId: string, assignmentId: string) => void;
  setPaperData: (data: QuestionPaperOutput) => void;
  setError: (error: string) => void;
  reset: () => void;
}

export const useAssessmentStore = create<AssessmentState>((set) => ({
  status: 'idle',
  jobId: null,
  assignmentId: null,
  paperData: null,
  error: null,
  
  setStatus: (status) => set({ status }),
  setIdentifiers: (jobId, assignmentId) => set({ jobId, assignmentId }),
  setPaperData: (paperData) => set({ paperData, status: 'done' }),
  setError: (error) => set({ error, status: 'failed' }),
  reset: () => set({ status: 'idle', jobId: null, assignmentId: null, paperData: null, error: null }),
}));

```

## **4. Real-Time Integration (WebSocket)**

The frontend uses a custom React hook to manage the Socket.io connection lifecycle. It joins a room specific to the `assignmentId` and updates the Zustand store upon receiving backend events.

```typescript
// src/hooks/useSocket.ts
import { useEffect, useRef } from 'react';
import { io, Socket } from 'socket.io-client';
import { useAssessmentStore } from '@/store/useAssessmentStore';

const SOCKET_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:4000';

export function useSocket(assignmentId: string | null) {
  const socketRef = useRef<Socket | null>(null);
  const { setStatus, setError } = useAssessmentStore();

  useEffect(() => {
    if (!assignmentId) return;

    // Initialize connection
    socketRef.current = io(SOCKET_URL, { transports: ['websocket'] });

    // Join specific room
    socketRef.current.emit('join', assignmentId);

    // Listen for backend job updates
    socketRef.current.on('job:update', (data: { status: string; error?: string; paperId?: string }) => {
      if (data.status === 'processing') {
        setStatus('processing');
      } else if (data.status === 'done') {
        // Trigger fetch of final paper data using paperId/assignmentId
        setStatus('done'); 
      } else if (data.status === 'failed') {
        setError(data.error || 'Generation failed');
      }
    });

    return () => {
      socketRef.current?.disconnect();
    };
  }, [assignmentId, setStatus, setError]);
}

```

## **5. API Data Flow & Submissions**

### **5.1 Form Submission (POST)**

Because the form includes a file upload, data must be sent as `multipart/form-data`.

* **Action:** User clicks "Generate".
* **Process:**
1. `react-hook-form` validates inputs against the Zod schema.
2. Zustand `status` set to `submitting`.
3. Frontend constructs `FormData`, appending the PDF file and stringifying the JSON fields (like `difficultyDistribution`).
4. Fetch POST to `/api/assignments`.
5. Backend returns `assignmentId`.
6. Fetch POST to `/api/assignments/:id/generate` to trigger the queue.
7. Zustand updates with `assignmentId`, triggering the `useSocket` hook to connect.



### **5.2 Fetching the Result (GET)**

Once the WebSocket emits `status: "done"`, the frontend must fetch the generated paper.

* **Action:** Automatically triggered by WebSocket event.
* **Process:**
1. Fetch GET to `/api/assignments/:id/result`.
2. Store JSON payload in Zustand `paperData`.
3. Next.js router navigates to `/result/[id]`.

## **6. UI Components & Layout**

### **6.1 The Form (`CreateAssessmentForm.tsx`)**

Constructed using `shadcn/ui` components (`Form`, `FormField`, `Input`, `Select`).

* **File Dropzone:** Utilizes standard HTML5 Drag-and-Drop or `react-dropzone`, rendered with dashed borders to match Figma.
* **Validation:** Negative numbers and empty strings are blocked via Zod. `totalMarks` and `totalQuestions` enforce minimums of 1.

### **6.2 The Loading State**

While Zustand `status === 'processing'`, render a dedicated loading overlay with a spinner and progressive text (e.g., "Analyzing constraints...", "Generating questions...").

### **6.3 The Output Paper (`/result/[id]`)**

This view is styled like a physical exam paper, ignoring standard web app constraints to prioritize printability and structural hierarchy.

| Component | Responsibility | Styling / Layout |
| --- | --- | --- |
| **`PaperHeader`** | Displays Student Name, Roll No, Section inputs. | CSS Grid/Flexbox with bottom borders acting as write-in lines. |
| **`SectionBlock`** | Renders the Section Title and Instructions. | Bold typography, standard margins, `<hr />` dividers. |
| **`QuestionCard`** | Displays question text and metadata. | Flex row: Question text on the left. Difficulty `Badge` and Marks text aligned to the right. |
| **`ActionBar`** | Houses "Regenerate" and "Download PDF". | Sticky header or floating action button (FAB) setup. |
